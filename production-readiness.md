# Campus Maintenance Production Enhancement Scope

## Account and Data Model

The upgrade will preserve the current role-preview mode for product demonstrations while adding an account-aware path for live use. A signed-in user is identified through the platform’s existing OAuth account flow, and their submitted maintenance requests will be stored in the application database. Administrators can retain full oversight through role-aware protected APIs; staff workflow routing remains visible in the user interface until institution-managed role assignment is connected.

## Language Quality Workflow

The application now offers English, Shona, and Ndebele operational copy. Because language accuracy and campus terminology should be validated by people who use them daily, Shona and Ndebele selections will display a compact **community review** cue. The project includes a concise handoff checklist for a native-speaking reviewer to confirm vocabulary, tone, safety messaging, and local campus terms before production release.

## Request Evidence and Urgent Alerts

Reporters will be able to select a maintenance photo from their device and see the attachment in the submitted request. The backend model supports storing the attachment reference alongside the request. An urgent request will also create an operational activity alert for the project owner, and Android notification configuration will be included for a future production push-notification channel.

## Navigation and Status-Bar Direction

The app shell will use a consistent service-header treatment: a deep-navy native status bar, role identity, language control, and compact operational status badge. The navigation bar will remain touch-first on Android and adapt cleanly on web, with a clearer active indicator and raised central request action in the visual hierarchy.
