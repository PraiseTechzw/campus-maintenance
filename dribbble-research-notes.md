## Early Visual Patterns

The visual search surfaced several useful patterns. The field-service references consistently use a high-contrast “next job” card, a compact schedule or route context, and a task list that groups work by operational state. The maintenance-ticket reference uses a compact two-screen journey: rapid ticket creation followed by a focused tracking/detail view. The operations dashboard imagery suggests a stronger distinction between primary operational information and supporting KPI information, rather than treating every card as equally prominent.

## Original Adaptation Direction

For Campus Maintenance, these references suggest an original interface update: use a single dominant **next action/work order** surface for each role, treat the secondary cards as light operational supporting data, and use a subtle campus-map or building-route context only in request detail. The UI should keep the existing navy-and-blue campus identity, retain text labels alongside color for accessibility, and avoid copying source layouts or graphical assets.

## Additional Work-Order and Security Cues

The second visual search added a useful work-order mobile pattern: a narrow timeline card with a compact job-state row, an explicit start-work action, and a short detail block. It also surfaced darker security operations dashboards that isolate exceptional events and use high-contrast alert areas rather than applying alert colors indiscriminately to every metric. Campus Maintenance can adapt this by making the ICT dashboard lead with the next assigned job, and by giving Security one dark, focused alert panel for urgent incidents while keeping routine work on the lighter operational canvas.
