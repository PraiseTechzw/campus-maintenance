# Responsive Website Plan

## Desktop Information Architecture

The website retains the single Campus Maintenance product but changes its layout at wider widths. Desktop users receive a permanent left-side workspace rail, a compact service header, a primary content canvas, and a right-side operational context panel. Mobile retains the existing bottom tab navigation and prioritizes one-handed interaction.

| Viewport | Navigation | Main Content | Supporting Context |
|---|---|---|---|
| Android / narrow web | Bottom tab bar | One-column task and request flow | Sheets and modals |
| Tablet | Compact rail or header navigation | Two-column operational cards | Collapsible context |
| Desktop | Persistent workspace rail | Two-column dashboard and detailed queues | Fixed service context / account panel |

## Website Priorities

The default Student web workspace should offer a broad request overview beside an active-report list. Technician and Security web workspaces should surface a priority job queue and status context. The administrator website should have space for a broader queue lens, filters, sorting, and workload signals rather than a narrow mobile control rail.

The visual system remains Campus Care: deep navy for the service shell, a light operational canvas, blue for action and active states, and clear status wording. No mobile screen is removed; web layouts supplement it through responsive composition.
